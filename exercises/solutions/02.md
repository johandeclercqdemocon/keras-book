## 1. [measure]

```python
import numpy as np
from keras import ops

stored = float(ops.convert_to_numpy(ops.cast(2049.0, "float16")))
print("2049 as float16:", stored)

smallest = next(n for n in range(1, 5000) if float(np.float16(n)) != n)
print("smallest integer float16 cannot hold:", smallest)
```

```text
2049 as float16: 2048.0
smallest integer float16 cannot hold: 2049
```

A `float16` number has 11 significant bits, so it holds every integer up to 2048. Above 2048 the spacing between numbers is 2, and an odd integer falls between two neighbors. A count that grows past 2048 in `float16` stops growing when you add 1.

## 2. [break]

```python
import keras
import numpy as np
from keras import ops

def noisy_fixed(shape):
    return ops.convert_to_numpy(keras.random.normal(shape, seed=3))

print("integer seed, calls equal:", np.array_equal(noisy_fixed((4,)), noisy_fixed((4,))))

generator = keras.random.SeedGenerator(3)

def noisy_generator(shape):
    return ops.convert_to_numpy(keras.random.normal(shape, seed=generator))

print("SeedGenerator, calls equal:", np.array_equal(noisy_generator((4,)), noisy_generator((4,))))
```

```text
integer seed, calls equal: True
SeedGenerator, calls equal: False
```

An integer seed has no state, so the same integer always gives the same numbers. A `SeedGenerator` holds a counter that advances on each draw. A new generator with the same starting seed gives the same sequence, so the run stays repeatable.

## 3. [judge]

**Position:** write the layer with `keras.ops`.

**What a good answer weighs.** The cost of `keras.ops` is small: the names match NumPy and the documentation is one page. The benefit is that the layer works on every back end and with every Keras feature that traces a layer symbolically. The cost of `tf.*` is a permanent link to one back end. The reviewer's claim "we will never switch" is a prediction, and the chapter's measurements do not support or refute it. They show only that the portable choice is not harder to write.

**Strongest objection.** Some operations have no `keras.ops` twin, for example a TensorFlow-specific sparse operation. In that case `tf.*` is the right tool, and the layer should say that it is TensorFlow-only.

**What would overturn it.** A profile that shows a `keras.ops` function that is slower than its `tf.*` twin on the team's hardware, by an amount that matters for a real workload.
