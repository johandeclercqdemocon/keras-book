## 1. [measure]

```python
import keras
import numpy as np
from keras import layers

keras.utils.set_random_seed(0)
base = keras.Sequential([
    keras.Input((8, 8, 1)),
    layers.Conv2D(16, 3, padding="same", activation="relu"),
    layers.Conv2D(32, 3, padding="same", activation="relu"),
    layers.GlobalMaxPooling2D(),
])
base.trainable = False
model = keras.Sequential([base, layers.Dense(10)])
trainable = sum(int(np.prod(w.shape)) for w in model.trainable_weights)
print("trainable:", trainable, " all:", model.count_params())
```

```text
trainable: 330  all: 5130
```

The head has 32 × 10 + 10 = 330 weights. The two convolutions have 160 and 4,640.

## 2. [break]

```python
import keras
import numpy as np
from keras import layers

x = np.random.default_rng(0).random((32, 8, 8, 1)).astype("float32")
y = np.random.default_rng(1).integers(0, 10, size=(32,))
loss = keras.losses.SparseCategoricalCrossentropy(from_logits=True)

def run(recompile):
    keras.utils.set_random_seed(0)
    body = keras.Sequential([keras.Input((8, 8, 1)), layers.Conv2D(8, 3, activation="relu"),
                             layers.GlobalMaxPooling2D()])
    body.trainable = False
    model = keras.Sequential([body, layers.Dense(10)])
    model.compile("adam", loss)
    model.fit(x, y, epochs=1, batch_size=16, verbose=0)
    before = [w.copy() for w in body.get_weights()]
    body.trainable = True
    if recompile:
        model.compile("adam", loss)
    model.fit(x, y, epochs=1, batch_size=16, verbose=0)
    return any(not np.array_equal(a, b) for a, b in zip(before, body.get_weights()))

print("unfrozen without compile, base changed:", run(False))
print("unfrozen with compile,    base changed:", run(True))
```

```text
unfrozen without compile, base changed: False
unfrozen with compile,    base changed: True
```

Keras keeps the training function from the first `fit`. The change of `trainable` has no effect until `compile`. This is the rule of [Chapter 3](../../chapters/03-layers-and-weights.md), seen in a transfer setting. The mistake is easy: the model trains, the loss falls, and the base is still frozen.

## 3. [judge]

**Position:** freeze first and train the head. Fine-tune with a small learning rate only if the frozen result is not enough and a held-out set shows that fine-tuning helps.

**What a good answer weighs.** With 200 images, a model with millions of weights can memorize the set, and fine-tuning every layer is the case where that happens. The chapter's table gives the shape of the evidence: with few labels, the frozen base was ahead of the new network when the head was trained enough, and fine-tuning was in between. The first question is how far the vendor domain is from the team's domain. The chapter did not test a large domain gap, so it cannot say. The second question is the training budget of the head. The chapter's first table shows that an under-trained head can reverse the conclusion.

**Strongest objection.** A frozen base cannot adapt to a domain gap, so fine-tuning might be the only way to reach a useful score. This is true, and the way to learn it is to try both on a held-out set with several seeds.

**What would overturn it.** A held-out result in which fine-tuning beats the frozen base by more than the spread over seeds, with the same budget for the head.
