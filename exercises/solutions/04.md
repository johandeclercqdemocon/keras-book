## 1. [measure]

```python
import keras
from keras import layers

keras.utils.set_random_seed(0)

def siamese(features, width, shared_layer=True):
    left = keras.Input((features,), name="left")
    right = keras.Input((features,), name="right")
    if shared_layer:
        shared = layers.Dense(width, activation="relu", name="shared")
        left_out, right_out = shared(left), shared(right)
    else:
        left_out = layers.Dense(width, activation="relu", name="left_dense")(left)
        right_out = layers.Dense(width, activation="relu", name="right_dense")(right)
    joined = layers.Concatenate()([left_out, right_out])
    score = layers.Dense(1, name="score")(joined)
    label = layers.Dense(3, activation="softmax", name="label")(joined)
    return keras.Model([left, right], [score, label])

print("6 features, Dense(10):", siamese(6, 10).count_params())
```

```text
6 features, Dense(10): 154
```

The shared layer has 6 × 10 + 10 = 70 parameters. The concatenation has 20 values. The `score` head has 20 + 1 = 21 parameters, and the `label` head has 20 × 3 + 3 = 63. The total is 70 + 21 + 63 = 154.

## 2. [break]

```python
import keras
from keras import layers

keras.utils.set_random_seed(0)

def count(shared_layer):
    left = keras.Input((4,))
    right = keras.Input((4,))
    if shared_layer:
        shared = layers.Dense(8, activation="relu")
        a, b = shared(left), shared(right)
    else:
        a = layers.Dense(8, activation="relu")(left)
        b = layers.Dense(8, activation="relu")(right)
    joined = layers.Concatenate()([a, b])
    model = keras.Model([left, right], [layers.Dense(1)(joined), layers.Dense(3)(joined)])
    dense = [layer for layer in model.layers if isinstance(layer, layers.Dense)]
    return model.count_params(), len(dense)

print("shared  :", count(True))
print("separate:", count(False))
```

```text
shared  : (108, 3)
separate: (148, 4)
```

The separate model has 148 parameters, which is 40 more, and one more `Dense` layer. The lost property is the constraint that both inputs go through the same function. The shared model must give the same output for `(a, b)` and `(b, a)` in the first stage, apart from the order of the concatenation. The separate model can learn a different function for each side.

## 3. [judge]

**Position:** use the functional style by default and subclass only for a reason.

**What a good answer weighs.** The chapter measures one fact on each side. The functional model reports every shape in `summary()` before data arrives. The subclassed model reports `?` and zero parameters until it is called. The debugging argument is real: a subclass is plain Python and you can put a breakpoint in `call`. The functional style also lets you debug, but you debug the construction and not a loop of calls.

**Strongest objection.** A graph that has data-dependent control flow cannot be a functional model. A team that has such graphs will subclass anyway, and a single style across the code base has a value of its own.

**What would overturn it.** A count of shape bugs found at build time in the functional models of the team, against the time lost to indirection. If the count is zero over a year, the argument for the functional style is weak.
