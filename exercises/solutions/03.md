## 1. [measure]

```python
import keras
import numpy as np
from keras import layers

keras.utils.set_random_seed(0)

model = keras.Sequential([
    keras.Input((20,)),
    layers.Dense(10),
    layers.BatchNormalization(),
    layers.Dense(1),
])
trainable = sum(int(np.prod(w.shape)) for w in model.trainable_weights)
frozen = sum(int(np.prod(w.shape)) for w in model.non_trainable_weights)
print("trainable:", trainable, "non-trainable:", frozen)
```

```text
trainable: 241 non-trainable: 20
```

The count by hand: the first `Dense` has 20 × 10 + 10 = 210. `BatchNormalization` has 10 values of `gamma` and 10 of `beta`, which is 20 trainable. It has 10 moving means and 10 moving variances, which is 20 non-trainable. The last `Dense` has 10 + 1 = 11. The trainable total is 210 + 20 + 11 = 241.

## 2. [break]

```python
import keras
import numpy as np

class Fixed(keras.layers.Layer):
    def __init__(self, trainable_weight, **kwargs):
        super().__init__(**kwargs)
        self.trainable_weight = trainable_weight

    def build(self, input_shape):
        self.scale = self.add_weight(
            shape=(1,), initializer="ones", trainable=self.trainable_weight, name="scale")

    def call(self, x):
        return x * self.scale

x = np.random.default_rng(0).normal(size=(64, 3)).astype("float32")
y = x.sum(1, keepdims=True)
for flag in (False, True):
    keras.utils.set_random_seed(0)
    layer = Fixed(flag)
    model = keras.Sequential([keras.Input((3,)), layer, keras.layers.Dense(1)])
    model.compile(optimizer=keras.optimizers.SGD(0.05), loss="mse")
    model.fit(x, y, epochs=3, verbose=0)
    changed = float(layer.scale.numpy()[0]) != 1.0
    print("trainable =", flag, "-> scale changed:", changed)
```

```text
trainable = False -> scale changed: False
trainable = True -> scale changed: True
```

The optimizer updates only the trainable list. A weight with `trainable=False` is state that the layer owns, and the training loop leaves it alone.

## 3. [judge]

**Position:** yes, with one condition. The mechanism fits, but the update must happen in the right mode.

**What a good answer weighs.** A non-trainable weight is the correct place for state that the optimizer must not touch, and the `Counter` layer in the chapter shows that `assign_add` works inside `fit`. The chapter also shows that the layer sees batches, so the running maximum is a maximum over batches seen so far. The colleague must decide the mode. The `Counter` layer updates in both modes. A maximum that updates at inference changes the output of the model between two predictions, which makes the model a function of its history. Update in training mode only, with the `training` argument.

**Strongest objection.** Computing the maximum in a preprocessing step, once, over the whole training set, is simpler and cannot depend on the order of the batches.

**What would overturn it.** A requirement that the statistic must adapt in production, with a test that shows the adaptive version is stable under reordering of requests.
